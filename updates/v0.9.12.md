# TrackerTalk 0.9.12

A conversa de destino de uma continuidade volta a ler o contexto que recebeu.

## A instrução proibia a leitura que ela mesma pedia

Ao criar uma continuidade, o TrackerTalk abre o outro CLI com uma instrução
de assimilação: leia o contexto preservado, entenda, e não execute nada.

O problema estava dentro dessa instrução. Ela mandava ler o arquivo
integralmente e, duas frases depois, dizia **não execute comandos**. Para um
CLI que lê arquivo executando um comando, as duas ordens se anulam. O
assistente obedecia a proibição, o que é o comportamento correto diante do que
foi escrito, não lia nada, e respondia com um relatório declarando que não
tinha conseguido abrir o arquivo.

Do lado do TrackerTalk tudo funcionava: o contexto era montado, salvo e
entregue. Só que a conversa nova começava vazia, sem saber nada do que veio
antes, que é exatamente o contrário do que a continuidade existe para fazer.

A proibição sempre quis dizer **não modifique**. Agora ela diz isso. Ler passou
a ser explicitamente autorizado, inclusive quando exige um comando de leitura,
e tudo o que altera o projeto continua proibido: nada de editar arquivo,
instalar dependência, rodar build ou teste, ou retomar tarefa antiga.

## Onde isso aparecia

Depende de como cada CLI lê um arquivo. Claude Code, Gemini CLI e GitHub
Copilot CLI recebem o conteúdo por outro caminho e não esbarravam na
contradição. Codex e opencode leem por comando, e eram os afetados.

## O contexto agora chega perto para os dois

O arquivo de contexto é copiado para dentro da pasta do projeto quando o CLI
de destino lê por comando, porque é lá que ele tem permissão de olhar. Isso
valia só para o Codex; o opencode, que entrou na versão anterior, ficou de
fora. Agora vale para os dois, e a cópia continua sendo apagada assim que a
conversa de destino termina.

## Compatibilidade e dados

- Windows 10 ou 11 x64;
- instalação por usuário, sem privilégios administrativos;
- esquema de dados local: 1, igual ao das versões anteriores;
- dados, rastreios, projetos e imagens existentes são preservados;
- continuidades já criadas não são afetadas: a mudança vale para as próximas.

## Atualizando

Execute o instalador por cima da instalação atual. Conversas em
andamento podem continuar abertas.

## Observação do Windows

O instalador ainda não possui assinatura Authenticode. O Windows Defender
SmartScreen pode apresentar um aviso antes da execução. A página de
distribuição explica o que fazer e como verificar o arquivo.
